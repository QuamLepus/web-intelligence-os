# Web Intelligence OS implementation status

This status describes the code in this repository. It is not a promise that the
full long-term product plan is already shipped.

| Area | Current status | Important limitation |
|---|---|---|
| Topic discovery, crawling, search, APIs, web console | Existing foundation | Existing project behavior; not re-certified by the incremental tests in this change. |
| Grounded `/ask` and citations | Implemented against existing tenant index | Extractive answer only; not an autonomous crawl or independently verified answer. |
| Topic-to-report research | Async discovery + crawl jobs produce verbatim, timestamped, hashed excerpts with per-claim citations; cancellation is cooperative between source crawls and lifecycle webhooks cover completion, failure, and cancellation | Not LLM synthesis, independent source verification, or calibrated confidence; needs Celery workers/Beat and discovery providers. |
| Provenance ledger and manifest | Implemented with tenant-keyed Redis storage; optional HMAC export | Caller supplies provenance; older data is not backfilled; HMAC is not a public-key signature. |
| Knowledge graph | Tenant-isolated Redis entity/relationship API, bounded graph listing, and console canvas explorer | Exact alias resolution only; no fuzzy/AI resolution or automated extraction. |
| Dataset marketplace previews and artifact delivery | Completed crawl jobs can provide a tenant-verified, sanitized Redis sample (up to 500 rows / 2 MiB) referenced by a listing with a maximum 30-day TTL; callers may explicitly opt in to private, tenant-hash-namespaced JSONL artifacts (10 MiB maximum) in configured MinIO storage, with exact-byte read-back verification and a 30-day lifecycle rule; listing publication binds validated unexpired artifact metadata internally; free purchases with linked artifacts support buyer-scoped API downloads with exact-byte verification | Artifact persistence requires caller data-rights confirmation and is disabled by default; listing pointers are not exposed; listings without retained artifacts remain metadata-only; common identifier redaction remains heuristic, previews are not dataset downloads, missing previews return 503, and paid settlement remains unavailable. |
| Python SDK | Early installable client for ask, crawl, watch, research, discovery, tenant graph, workflows, discovery with manual review by default and explicit robots-aware auto-crawl, billing checkout-session creation and current/historical invoice estimate reads, public SSO configuration/audit reads, provenance, webhooks, Data Studio, tenant-scoped marketplace reads (paginated search, bounded sanitized crawl-sample previews, seller inventory, purchase history, reviews, bounty details/submissions, seller-owned listing updates, and buyer delivery retrieval), explicit free-listing purchases, tenant-owned published-dataset bounty submissions, poster-only awards of eligible submitted datasets, and one-time purchase-verified reviews; posters can create and cancel their own open bounties | Still incomplete endpoint coverage; paid settlement and reward transfers are unavailable; release and compatibility policy remain early. |
| Research console page | Authenticated UI for topic-to-report creation, progress, and cooperative cancellation; the separate `/app/research` page is a UI over `/ask` | Reports are extractive and not independently fact-checked; cancellation waits for the active source crawl to finish. |
| Web change monitoring | Scheduled URL watches, one-page crawl snapshots, content hashes, change history with bounded before/after excerpts, up to 20 tenant-scoped text snapshots per watch (5,000 characters each; 90-day retention), basic text-based price mentions, `web.changed` webhook event, a console that distinguishes empty watch lists/history from retrieval errors, labels the selected watch with a direct return-to-list link, handles stale or unverifiable selections and shows run/stop controls only for active watches, and watch-only public-address DNS pinning with redirect checks and bounded response size | Snapshots are text-only, not raw HTML/assets; no semantic change classification or structured product matching. Direct watch fetches require worker egress to public hosts and do not use ambient HTTP proxy settings. Celery Beat and workers must run. |
| Data Studio | Authenticated own-index query explorer with bounded search preview/export, tenant-scoped saved queries and immutable result snapshots, plus full-corpus SQLite aggregates (source/host/language/snapshot/day; count and mean authority/quality/body length), filters, pagination, charts, and page-aware aggregate CSV; the console distinguishes saved-query and snapshot retrieval errors from successful empty lists | Full-corpus analysis returns aggregates rather than document rows (up to 100 groups/request; the console displays/exports 50 groups per page; offset capped at 5,000) and may scan SQLite; no arbitrary SQL or full-corpus materialization. Search-result snapshots cover at most 100 hits, expire after 90 days, and are capped per tenant/size. A 50k-row synthetic warm-cache baseline is recorded; production-scale analytics latency remains unverified. |
| Workflow builder | Tenant-scoped sequential and dependency-DAG crawl recipes with create/list/edit/delete/run/status APIs, console and SDK controls, Celery execution, DAG-aware per-step status/progress, robots checks, request-budget accounting, cooperative cancellation, recurring schedules, and 30-day run-history search/status/inclusive-date filters backed by tenant-scoped indexes and a documented synthetic benchmark; the console distinguishes run-history or workflow-list retrieval errors from successful empty results and explains when a selected run overlay cannot be retrieved. Definition changes and schedule ticks share a short Redis lock; deletion is blocked while runs are queued/running. | Crawl-only (up to 10 steps / 25 pages each); DAG nodes are serial, not parallel; failed nodes skip descendants while independent branches continue. No arbitrary code or conditional predicates. The console has a read-only SVG graph preview and per-step prerequisite checkboxes for editing DAG edges; there is no drag-and-drop graph editor. Existing tenants pay a one-time lazy filter-index backfill; schedules require Celery Beat plus workers; cancellation waits for the active crawl step to finish. |
| Agent marketplace | Tenant-authenticated declarative agent-card catalog with drafts, owner-only edits, published-card search, bounded versioned input/output schemas, and a server-rendered `/app/agents` console for paginated browse/detail and owner views with lifecycle-status filtering, editable listing metadata, draft publish/unpublish, and owner archive/restore; one server-managed deterministic `data-curator` can run bounded, ephemeral inputs; multi-backend publisher-runtime threat model, infrastructure readiness matrix, rollout sequence, and launch gates documented for WASM/WASI, sandboxed Kubernetes, and microVM targets; strict non-executing attestation/admission/audit contracts and fail-closed exact-backend policy requiring Ed25519 signature verification against validity/revocation-aware trusted-key records, dual-signed backend-readiness assertions (independent assessor plus operator with distinct Ed25519 keys), with artifact-review keys and signer identities also distinct from both readiness roles, bound to the exact pool/environment ID and current readiness generation with per-backend isolation gate requirements, fresh structured gate reports bound to backend/pool/policy, with both report and source-evidence bytes matched to signed digests and separate trust sets; matching size-limited artifact bytes, a default 90-day maximum artifact-attestation age, and explicit artifact-revocation denial; tenant-partitioned Redis audit ledger with bounded retention, optimistic append, SHA-256 hash-linked verification, retained-window anchors, and caller-exported Ed25519 signed checkpoints | Managed curation uses uncalibrated heuristics (not a safety guarantee); no paid access/settlement, seller-card execution, publisher code/container uploads, or verification of claimed capabilities. Runtime backends remain design-only, not provisioned or validated; admission policy and audit ledger are not integrated into runtime paths, and the Redis hash chain is not immutable; external anchoring requires operators to export and retain signed checkpoints separately. Existing dataset marketplace remains separate. See `docs/agent-marketplace.md` and `docs/agent-runtime-security.md`. |
| Enterprise connectors, SSO, compliance | Early tenant-configured OIDC Authorization Code + PKCE SSO, encrypted client secrets, verified-domain JIT controls, and bounded SSO audit history with console feedback distinguishing retrieval errors from empty history | Requires Enterprise plan and operator-managed encryption/public-base secrets; same-host HTTPS OIDC endpoints and RS256 only. No SAML, SCIM, deprovisioning sync, IdP MFA enforcement, complete compliance audit, or SOC 2/ISO certification. Live IdP and multi-replica validation remain. See `docs/enterprise-sso.md`. |
| Billing | Stripe-backed checkout, usage and webhook application; opt-in real test-mode Checkout integration and a secret-gated Stripe CLI HTTP-delivery smoke | Requires a Stripe test key and recurring test Price; the CLI delivery uses a generated fixture event, not completion of the Checkout Session, and neither the API call nor CLI delivery can run here without credentials. See `docs/stripe-testing.md`. |
| Observability and tracing | API OpenTelemetry spans, low-cardinality Prometheus HTTP metrics (unmatched paths use a fixed label), Sentry hooks, and Celery W3C trace-context propagation with producer/task spans | OTLP export requires the optional `requirements-otel.txt` exporter and a configured collector; no production sampling, collector availability, backpressure, or end-to-end staging validation yet. Span attributes intentionally exclude tenant IDs, URLs, task payloads, and exception messages. |
| Python dependency profiles | Separate API, worker, optional AI, browser, development, search-index, and OTLP profiles; PR CI loads each service-specific Docker target, reports its Docker virtual size, and archives per-image reports; post-publish CI pulls all four GHCR application images, reports and archives their virtual sizes, and smoke-tests core Compose services including the dashboard, workers, Beat, and backing services | Profiles use version ranges, not a lockfile; reported size is the uncompressed Docker virtual size (not compressed registry transfer size). Compose smoke validates core-service readiness (MinIO only when Quay credentials are configured) but does not run the external-crawl CLI or test application integration with every backend. |
| Performance measurement | Reproducible synthetic own-index query benchmark plus sequential and threaded in-process Data Studio API baselines are recorded | No production-scale or network-level load tests, multi-process/replica concurrency, reranking, LCP/CLS, or cloud-cost benchmarks; targets remain unverified. |
| TypeScript SDK + MCP server | Early packages cover ask, crawl, research, discovery, tenant graph, watch, workflows, billing checkout-session creation and current/historical invoice estimate reads, public SSO configuration/audit reads, provenance, webhooks, Data Studio, and marketplace reads including paginated search/history, bounded sanitized crawl-sample previews, seller inventory and listing updates, reviews, bounty details/submissions, and buyer deliveries; the TypeScript SDK supports explicit robots-aware automatic discovery crawling and free-listing purchases, tenant-owned published-dataset bounty submissions, poster-only awards of eligible submitted datasets, one-time purchase-verified reviews, poster-only bounty creation and cancellation. MCP adds validated `YYYY-MM` historical invoice-estimate reads and intentionally exposes marketplace reads only. CI builds/tests both and checks package tarballs; MCP stdio smoke tests cover initialize/list/call/error paths. | Not published to npm; paid settlement and reward transfers are unavailable; live API integration, complete endpoint coverage, and a stable compatibility/release policy remain. |

The implemented endpoints are tenant authenticated and tested with fakeredis.
Production deployments must configure Redis and protect
`WCP_PROVENANCE_SIGNING_KEY` using their secret-management system. The signing
key is intentionally optional: manifest export returns `503` if it is absent.
